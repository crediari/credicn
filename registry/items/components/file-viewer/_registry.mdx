Preview files in a responsive, accessible dialog. The component supports images, PDF, video,
audio, text/code, CSV, TSV, XLSX, and XLSM, along with keyboard navigation, downloads, scroll zoom,
and image rotation. The viewer uses the application’s dark theme even when the page uses the light
theme, with a `background/80` overlay. Click the backdrop outside the file to close it.
The toolbar uses `position: absolute`, centered at the bottom, overlaying the preview without
reserving space or reducing the viewing area. PDFs support continuous vertical scrolling, current
and total page indicators, direct page navigation, zoom, and fit to screen. Images support zoom
and rotation; other formats show file details and downloads. Playback controls stay next to audio
and video. PDFs use PDF.js rather than Chrome’s native reader or an iframe. PDF, text, and
spreadsheets are processed in the browser.
While the dialog is open, page scrolling is locked and restored to its previous position on close,
including on mobile browsers.

```tsx
import { useState } from "react";

import { FileViewer, type FileViewerFile } from "@/components/ui/file-viewer";

const files: FileViewerFile[] = [
  { id: 1, name: "contract.pdf", size: 245_800 },
  { id: 2, name: "forecast.xlsx", size: 89_400 },
];

export function Attachments() {
  const [open, setOpen] = useState(false);

  return (
    <>
      <button onClick={() => setOpen(true)}>Preview arquivos</button>
      <FileViewer
        files={files}
        open={open}
        onOpenChange={setOpen}
        resolveFile={async (file, signal) => {
          const response = await fetch(`/api/files/${file.id}`, { signal });
          if (!response.ok) throw new Error("Failed to load file");
          return response.blob();
        }}
      />
    </>
  );
}
```

You can also provide a `source` for each file as a URL, `Blob`, `ArrayBuffer`, or `Uint8Array`.
Use `renderPreview` for app-specific formats and `onDownload` when downloads require a custom API.
Legacy XLS files can use the optional Office preview. URLs used by PDF.js, text, and spreadsheets
must allow `fetch` through the same origin or CORS. For authenticated files, `resolveFile` can fetch
with the required credentials and return a `Blob`. PDF read errors and Office conversion errors
are also sent to `onError`.

### Optional Office Preview

The component recognizes DOC/DOCX/DOCM, PPT/PPTX/PPTM, XLS/XLSB, ODT/ODP/ODS, and RTF.
Office documents are previewed exclusively through a PDF supplied by the application. Without
`officePreview`, the document remains downloadable and a message explains that conversion is missing.

**PDF conversion:** provide a function returning a PDF version of the document. Your application
implements the conversion, for example through a backend service. This works with private files,
URLs, `Blob` values, and buffers, reusing continuous scrolling and PDF controls. Downloads still
use the original file. The function receives the file, its resolved source, and an `AbortSignal`
to cancel when the viewer closes or switches files.

```tsx
<FileViewer
  files={files}
  open={open}
  onOpenChange={setOpen}
  officePreview={async (file, source, signal) => {
    // Your application must provide this endpoint to convert the document to PDF.
    const response = await fetch(`/api/files/${file.id}/preview.pdf`, { signal });
    if (!response.ok) throw new Error("Failed to convert document");
    return response.blob();
  }}
/>
```

`renderPreview` remains available for custom renderers and replaces both the preview and its toolbar.

### PDF.js Worker

The worker loads as a local asset through `pdfjs-dist/build/pdf.worker.min.mjs?url` (Vite).
For another bundler, adapt the import to its asset strategy or supply `pdfWorkerSrc` with an
application-hosted worker URL using the **same version** as `pdfjs-dist`. Your CSP must allow
the worker and file loading. The PDF is a read-only preview: form fields and internal links
are not interactive.

### Keyboard Shortcuts

| Key | Action |
| --- | --- |
| `Esc` or click the backdrop | Close the viewer |
| `←` / `→` | Previous / next file (wraps around) |
| `+` or `=` / `-` | Zoom in / out on the image or PDF |
| `Ctrl/Cmd` + scroll | Zoom the PDF in 25% steps |
| `PageUp` / `PageDown` | Native scrolling when the PDF area is focused |
| `R` | Rotate the image by 90° |
| `0` | Reset zoom and rotation |

For images, mouse or trackpad scrolling adjusts zoom between 25% and 400% in 25% steps,
accumulating small movements with a minimum interval of 120 ms between steps. Images have no
shadow, preserving PNG transparency. Normal scrolling navigates PDF pages; Ctrl/Cmd + scroll
adjusts zoom in the same steps.
Click and drag a zoomed image to pan in any direction; the hand cursor indicates when it can be
moved. Scrollbars remain available. Switching files or reopening the viewer resets zoom and
rotation. Shortcuts respect editable fields, media controls, and Ctrl, Alt, or Cmd combinations.
Enter a page number and press Enter or leave the field. Values above the total go to the last
page; invalid values restore the current page. The indicator follows scrolling without page
turning buttons. Only pages near the visible area keep their canvas rendered, limiting memory use.

### Demo Scenarios

The preview includes landscape, portrait, and transparent images; a two-page PDF; WAV audio
and MP4 video; basic CSV and CSV with special fields; TSV; Excel with multiple sheets, dates,
and formulas; Markdown, JSON, and long logs. It also covers an empty file, an unsupported format,
slow loading, load failure, corrupted images, PDFs, and spreadsheets, and an empty gallery.
All files and data are fictional and local.

The Office demo simulates PDF conversion: the local sample PDF demonstrates scrolling and
controls without actually converting the documents. Downloads preserve the original DOCX/PPTX.
