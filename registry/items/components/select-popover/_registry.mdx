Provide `getItemValue` and `getItemLabel` to use any item shape. The popover automatically matches
the trigger width. Search is accent-insensitive and can include extra fields through
`getItemKeywords`.

## Single selection

```tsx
import { SelectPopover } from "@/components/ui/select-popover";

<SelectPopover
  items={cities}
  value={city}
  onValueChange={setCity}
  getItemValue={(item) => item.id}
  getItemLabel={(item) => item.name}
  getItemKeywords={(item) => [item.state]}
  resultLimit={50}
  clearLabel="Todas as cidades"
/>
```

`resultLimit` defaults to `100`. Only that many filtered items are mounted, keeping large datasets
from creating an oversized DOM. A message asks the user to refine the search when more results are
available. In single selection, `clearLabel` adds an option that resets the value to `null`.
Use `triggerId` to associate a label and `portalContainer` to keep the popover inside a dialog
or sheet when needed.

## Multiple selection and custom content

```tsx
<SelectPopover
  multiple
  items={users}
  value={selectedUsers}
  onValueChange={setSelectedUsers}
  getItemValue={(user) => user.id}
  getItemLabel={(user) => user.name}
  getItemKeywords={(user) => [user.email]}
  renderValue={(users) => `${users.length} selecionados`}
  renderItem={(user) => (
    <div className="flex items-center gap-3">
      <img src={user.avatarUrl} alt="" className="size-8 rounded-full" />
      <div>
        <p>{user.name}</p>
        <p className="text-xs text-muted-foreground">{user.email}</p>
      </div>
    </div>
  )}
/>
```

Multiple selection keeps the popover open by default so several items can be toggled. Use
`closeOnSelect` to change that behavior. For server-side search, control `searchValue`, handle
`onSearchValueChange`, and set `shouldFilter={false}`.
